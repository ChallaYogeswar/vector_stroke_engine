## 1. What the project is

A **client-side photo tool**. You upload an image; it is cleaned up (denoise → spot removal →
sharpen, in a Web Worker); then it is rendered by one of five engines onto a single canvas:

| Mode id | What it renders | Theme |
|---|---|---|
| `2d` | Posterized, flat "vector-style" image | dark |
| `sketch` | Animated pen-stroke line drawing: Canny-style contours traced into smooth strokes + optional hatching (flagship) | dark |
| `histogram` | R/G/B + luminance distribution chart | **light** ("print report") |
| `ascii` | Character-art with typewriter reveal | dark |
| `3d` | Photo hung like a picture and pushed into a smooth WebGL relief; stable, user-controlled camera (drag/zoom/reset, optional sway); 2D fallback if no WebGL | dark |

Extras: settings drawer (cleanup toggles + per-mode sliders), export (PNG for all; SVG for Sketch,
TXT for ASCII, CSV for Histogram; Web Share API where available), and an **optional** Vercel
serverless backend (`/api/describe`, `/api/path-feeder`) that calls Anthropic's Messages API.
**No UI calls the backend yet** (deliberate; see section 10).

## 4. Data contracts (the locked core)

### 4.1 `src/engine/types.ts`

```ts
export interface Point { x: number; y: number }
export interface Layer { name: string; stroke: string; points: Point[] }      // Sketch: one Layer = one pen stroke
export interface ImageMeta { width: number; height: number; totalPoints: number; layers: number }
export interface StrokeData { meta: ImageMeta; layers: Layer[] }

export type ModeId = 'sketch' | '2d' | '3d' | 'histogram' | 'ascii';

export type RenderPayload = RasterPayload | HistogramPayload | AsciiPayload | Relief3DPayload;
export interface RasterPayload    { kind: 'raster'; imageData: ImageData }
export interface HistogramBins    { red: number[]; green: number[]; blue: number[]; luminance: number[]; maxCount: number } // each 256 long
export interface HistogramPayload { kind: 'histogram'; bins: HistogramBins }
export interface AsciiPayload     { kind: 'ascii'; cols: number; rows: number; chars: string[] }            // row-major, len cols*rows
export interface Relief3DPayload  { kind: 'relief3d'; cols: number; rows: number; heights: number[]; colors: string[] } // heights 0..1, colors '#rrggbb'

export interface RenderContext { canvas: HTMLCanvasElement; ctx: CanvasRenderingContext2D; width: number; height: number }

export interface ModeEngine {
  readonly id: ModeId;
  process(image: ImageData): StrokeData | RenderPayload;   // once per image/mode-switch/settings change
  render(ctx: RenderContext, progress: number): void;      // one frame; progress 0..1

}
```

on each mode class (not on the interface).

## 6. Engine reference (`src/engine/`)

All luminance uses **Rec.709**: `L = 0.2126 R + 0.7152 G + 0.0722 B`.

### 6.1 `math.ts`
```ts
export function clamp(value: number, min: number, max: number): number      // value<min?min : value>max?max : value (no rounding)
export function clamp01(value: number): number                              // clamp(value, 0, 1)
export function cellRange(index: number, count: number, sourceSize: number): [number, number]
// [start,end) source-pixel range of grid cell `index` of `count` along an axis; guaranteed non-empty:
//   start = min(sourceSize-1, floor(index/count*sourceSize))
//   end   = min(sourceSize, max(start+1, floor((index+1)/count*sourceSize)))
```
Callers that need integers call `Math.round` themselves first.

### 6.2 `theme.ts`
Canvas cannot read CSS variables, so this reads them at draw time.
```ts
export interface ThemeColors { accent; accentStrong; textPrimary; textSecondary; textTertiary; border; surface: string }
export function readThemeColors(): ThemeColors   // reads --accent, --accent-strong, --text-primary, --text-secondary, --text-tertiary, --border, --surface from documentElement
export function withAlpha(hex: string, alpha: number): string  // '#rrggbb' → 'rgba(r, g, b, a)'; non-6-digit-hex input returned unchanged
```
Fallbacks (used when no `document`/`getComputedStyle`, e.g. tests, or empty var): accent `#46e0a0`, accentStrong `#7dffc7`, textPrimary `#e9eaec`, textSecondary `#9ba0a8`, textTertiary `#5c6169`, border `#262a30`, surface `#15171b`.

### 6.3 `timeline.ts` — `class Timeline`
rAF-driven progress ticker. `new Timeline({ durationMs = 2000, loop = false })`.
- `onTick(listener): () => void` (returns unsubscribe)
- `get progress` → `min(1, elapsed/duration)` (1 if duration ≤ 0)
- `get isRunning`
- `setDuration(ms)`, `setLoop(bool)`
- `play()` (no-op if running; resets `lastFrameTime`), `pause()` (cancels rAF), `reset()` (pause + elapsed=0 + notify)
- tick: adds `now - lastFrameTime`; at/after duration: if `loop` → `elapsed %= duration` and continue; else clamp to duration, `running=false`, notify, stop. Otherwise notify and schedule next rAF.

### 6.4 `controller.ts` — `class Controller`
Mode router. Holds `Map<ModeId, ModeEngine>`, `activeId`, `currentImage`, `currentOutput`.
- `register(engine)`, `get registeredModes: ModeId[]`, `get activeMode`, `get output`
- `setImage(image)` — stores image, nulls output; does **not** process
- `switchTo(id)` — throws `Controller: no engine registered for mode "<id>"` if unknown; throws `Controller: switchTo() called before setImage() — nothing to process yet.` if no image; else sets active, runs `engine.process(image)`, stores + returns output. Calling it with the *same* id = "reprocess with current settings" (this is how settings changes are applied).
- `render(ctx, progress)` — no-op if no active mode
- `reset()` — every engine's `reset()`, clears active/image/output

### 6.5 `preprocess/cleanup.ts` — pure pipeline
```ts
export interface CleanupOptions {
  denoise:     { enabled: boolean };
  spotRemoval: { enabled: boolean; darknessThreshold: number; neighborhoodRadius: number; maxSpotArea: number };
  sharpen:     { enabled: boolean; amount: number; radius: number };
}
export const DEFAULT_CLEANUP_OPTIONS: CleanupOptions = {
  denoise: { enabled: true },
  spotRemoval: { enabled: true, darknessThreshold: 26, neighborhoodRadius: 6, maxSpotArea: 40 },
  sharpen: { enabled: true, amount: 0.6, radius: 2 },
};
export function cleanupImage(image, options = DEFAULT_CLEANUP_OPTIONS): ImageData   // clone → [median3x3] → [removeBlemishes] → [unsharpMask]; input untouched
export function medianFilter3x3(image): ImageData
export function removeBlemishes(image, options: CleanupOptions['spotRemoval']): ImageData
export function keepSmallComponents(mask: Uint8Array, width, height, maxArea): Uint8Array
export function unsharpMask(image, amount, radius): ImageData
export function cloneImageData(image): ImageData
export function boxBlurChannel(values: Float64Array, width, height, radius): Float32Array
```
- **medianFilter3x3**: per-RGB-channel median of the 3×3 window, edges clamped; alpha copied. 9-element insertion sort into three `Uint8ClampedArray(9)` windows.
- **removeBlemishes**: luminance + box-blurred (radius `neighborhoodRadius`) luminance/R/G/B. Candidate = `localLum − lum > darknessThreshold`. `keepSmallComponents` keeps 4-connected components of size ≤ `maxSpotArea`. Kept pixels get RGB replaced by the blurred RGB (rounded, clamped). Alpha untouched.
- **keepSmallComponents** (**correctness-critical**): iterative flood fill with an `Int32Array` stack. Once a component exceeds `maxArea` it stops *collecting* pixels but the fill **keeps walking to the end** so every pixel of a big region is marked visited (an early `break` used to leave fragments that were then misclassified as small blemishes). Only components with `!tooBig && size ≤ maxArea` reach the output mask.
- **unsharpMask**: `out = round(v + amount × (v − blur(v)))` per RGB channel, clamped 0–255, alpha copied.
- **boxBlurChannel**: summed-area table (`Float64Array((w+1)(h+1))`), O(1) per pixel, window clamped at borders, divides by actual window area; `radius ≤ 0` returns a `Float32Array` copy.

```ts
export function handleCleanupRequest(req): CleanupWorkerResponse   // pure: ImageData → cleanupImage(options ?? DEFAULT) → response
```
At module load, installs `self.onmessage` **only if inside a real worker**, detected by `typeof self.importScripts === 'function'` (jsdom's `window` also has `postMessage`, so that alone is not a valid probe). Replies with `postMessage(response, [response.data.buffer])`. `self` is re-typed locally (DOM lib vs WebWorker lib conflict).

### 6.7 `preprocess/cleanup-client.ts`
```ts
export interface CleanupWorkerClient { run(image: ImageData, options: CleanupOptions): Promise<ImageData>; terminate(): void }
export function createCleanupWorkerClient(): CleanupWorkerClient
```
- If `typeof Worker === 'undefined'` → synchronous fallback client (`Promise.resolve(cleanupImage(...))`).
- Else lazily creates ONE persistent module worker: `new Worker(new URL('./cleanup-worker.ts', import.meta.url), { type: 'module' })` (this literal form is what makes Vite emit the separate worker chunk — do not indirect it).
- `run`: assigns `requestId`, stores `{image, options, resolve}` in a `Map`, **copies** the pixel buffer (`image.data.buffer.slice(0)`) before transferring it (so the caller's `ImageData` stays usable), posts.
- `onmessage`: looks up by `requestId`, resolves `new ImageData(data, width, height)`; unknown ids ignored.
- `onerror`: resolves every pending request by running `cleanupImage` on the main thread, clears the map, terminates + drops the worker (next `run` starts a fresh one).
- `terminate()`: terminate + clear.

### 6.9 `modes/sketch-trace.ts` + `modes/mode-sketch.ts` — Sketch (`id: 'sketch'`) — flagship

**History / why it is built this way.** The first version sampled one strongest-edge pixel per grid cell and joined them with a nearest-neighbour walk. On real photos (especially dark ones) that produced a *maze of zig-zag squiggles*, not a drawing, because it never followed actual contours and had no exposure handling. It was replaced wholesale by the pipeline below (the old `orderIntoPaths`, `pointBudget`, `edgePercentile`, spatial-hash code and their tests are gone).

#### `sketch-trace.ts` (pure functions, no canvas/theme; works in a *working space* with long edge ≤ `WORKING_MAX_DIM = 720`)
```ts
export const WORKING_MAX_DIM = 720;  export const EDGE_BLUR_SIGMA = 1.3;
export interface ToneMap { width; height; sx; sy; tone: Float32Array }   // sx/sy = source px per working px (>=1)
export function buildToneMap(image: ImageData, maxDim = 720): ToneMap
export function gaussianBlur(src: Float32Array, w, h, sigma): Float32Array          // separable, edges clamped
export function detectEdges(tone, w, h, sensitivity: number): Uint8Array            // 1 = edge pixel
export interface TracedStroke { points: Point[] /*working space*/; length: number /*px, pre-simplification*/ }
export function traceContours(edges, w, h, minLength: number): TracedStroke[]
export function smoothPolyline(points, passes): Point[]                             // [1 2 1]/4, endpoints pinned
export function simplifyPolyline(points, tolerance): Point[]                        // iterative Ramer–Douglas–Peucker
export interface HatchStroke { a: Point; b: Point; level: 0 | 1 | 2 }
export function buildHatching(tone, w, h, shading: number): HatchStroke[]
```
- **buildToneMap**: area-average downscale of Rec.709 luminance (`factor = max(1, longEdge/maxDim)`, never upsamples), then **auto-level**: stretch the 1st–99th percentile to 0..1, then a gamma (clamped 0.4–1.6) that moves the median to 0.5. This is what makes a dark/underexposed photo give the same quality of lines as a well-exposed one. **Near-flat images** (1st→99th percentile spread < 8) skip stretching and keep true brightness (`L/255`) — otherwise a plain white page would be treated as black and hatched everywhere (real bug caught by a test).
- **detectEdges** (Canny recipe): Gaussian blur σ 1.3 → Sobel (÷4, so a full black→white step ≈ 1) → **non-maximum suppression** (gradient direction quantised to 4 axes; 1px-thin ridges; magnitudes < 0.02 ignored) → **hysteresis**: `keep = 0.08 + 0.42·sensitivity` is the fraction of ridge pixels treated as "sure" edges (`high` = that percentile, floored at `MIN_STRONG_EDGE = 0.07` so flat/noisy images yield *nothing* instead of a maze); `low = 0.42·high`; weak ridge pixels survive only if 8-connected to a sure edge (stack flood-fill).
- **traceContours**: pass 1 starts walks at **endpoints** (exactly one neighbour) so open curves come out as single strokes; pass 2 handles loops/leftovers (walked both directions from the start pixel and merged). The walk prefers the neighbour that keeps the heading straightest (cosine with previous step, +0.05 bonus for 4-connected steps). Chains shorter than `minLength` are dropped. Kept chains → pixel centres (+0.5) → `smoothPolyline(…, 2)` → `simplifyPolyline(…, 0.65)`.
- **buildHatching**: tone blurred σ 2.2; `t0 = 0.18 + 0.32·shading`; thresholds `[t0, 0.66·t0, 0.36·t0]` for levels 0/1/2 = 45° lines, −45° lines, horizontal lines (level 2 spacing ×1.5). Line spacing `max(4, round(longEdge/105))`. Each line is sampled every 1px; runs where tone < threshold and length ≥ `max(4, spacing)` become a 2-point stroke. `shading ≤ 0.001` → `[]`.

#### `mode-sketch.ts`
```ts
export interface SketchOptions { sensitivity: number; minStrokeLength: number; shading: number; strokeWidth: number }
export const DEFAULT_SKETCH_OPTIONS = { sensitivity: 0.65, minStrokeLength: 12, shading: 0.5, strokeWidth: 1.4 };
export const SKETCH_SENSITIVITY_RANGE       = { min: 0.05, max: 1 }  as const;   // UI label "Detail"
export const SKETCH_MIN_STROKE_LENGTH_RANGE = { min: 4,    max: 60 } as const;   // rounded; UI label "Line cleanup"; working-space px
export const SKETCH_SHADING_RANGE           = { min: 0,    max: 1 }  as const;   // 0 = off
export const SKETCH_STROKE_WIDTH_RANGE      = { min: 0.5,  max: 3 }  as const;
configure(partial)   // clamps all four
```
`process(image)`: tone map → `detectEdges` → `traceContours` sorted **longest first** → layers `Contour i` (stroke = `theme.accentStrong`, points scaled to source coords by `sx/sy`) → hatching sorted by **`level` then `y`** (light pass sweeps top→bottom, then the crossing pass, then the deepest — like hatching/cross-hatching; grouping by tint is also what lets render batch) → layers `Shade i` (2 points; stroke = `accent` at alpha 0.55 / 0.47 / 0.40 for levels 0/1/2). `meta = { width, height, totalPoints, layers }` (source-image size).

`render(ctx, progress)`: clear; no data → return; `totalPoints === 0` → centered `NO STRONG EDGES DETECTED`; scale-to-fit + center; `budget = floor(progress·totalPoints)` (min 1 if progress > 0). **Batching:** consecutive complete layers with the same `stroke` string share one `beginPath()…stroke()` (a flush happens only when the colour changes), so thousands of hatch lines cost ~4 draw calls/frame. Contours: `lineWidth = strokeWidth`, `shadowBlur 1.5`; hatch: `lineWidth = strokeWidth × 0.7`, no shadow. The one in-progress layer is drawn separately with `shadowBlur 6` plus a 1.8px glowing pen-tip dot. `lineJoin/lineCap = round`.
Duration (in `useEngine`): `clamp(totalPoints × 18, 1200, 5000)` ms.

### 6.10 `modes/mode-histogram.ts` — `class ModeHistogram` (`id: 'histogram'`)
No options. `process()`: one pass, 256 buckets each for R, G, B and luminance (`min(255, round(L))`); `maxCount = max(1, largest bucket across all four)`. `render()`: pad `{top 28, right 20, bottom 28, left 20}`; baseline axis in `theme.border`; legend row at `chartY − 14` (`LUMINANCE` in textSecondary, `RED #c1443c`, `GREEN #3f8f5c`, `BLUE #3f6fb0`; font `500 10px "JetBrains Mono"`); `rise = easeOutCubic(clamp01(progress))`; bar height = `√count / √maxCount × chartH × rise` (**sqrt scale**); luminance drawn first as filled silhouette (`accent` α 0.16 fill, α 0.55 outline), then R/G/B as 1.2 px lines at α 0.85. RGB lines use literal red/green/blue on purpose (an exception to theming).

### 6.11 `modes/mode-ascii.ts` — `class ModeASCII` (`id: 'ascii'`)
Constants: `RAMP = ' .:-=+*#%@'` (10 levels), `MAX_COLS 140`, `MIN_COLS 8`, `MAX_ROWS 90`, `MIN_ROWS 6`, `CHAR_ASPECT 0.5`.
```ts
export interface ASCIIOptions { targetCols: number | null }        // null = auto (image width)
export const DEFAULT_ASCII_OPTIONS = { targetCols: null };
export const ASCII_TARGET_COLS_RANGE = { min: 8, max: 140 } as const;
configure(partial)   // undefined keeps current; null = auto; number → round + clamp
```
`process()`: `cols = clamp(targetCols ?? width, 8, 140)`; `rows = clamp(round(cols × height/width × 0.5), 6, 90)`; each cell's average luminance → `RAMP[round(L/255 × 9)]` (**brighter → denser glyph**, inverse of ink-on-paper, because the theme is a dark terminal). Cell pixel range via `cellRange`.
`render()`: `cellWidth = max(1, min(width/cols, (height/rows) × 0.5))`, `cellHeight = cellWidth / 0.5` (**rectangular cells**, so on-canvas art keeps the same proportions as the `.txt` export); grid centered; `revealed = floor(progress × total)` (min 1 if progress > 0), row-major; font `500 ${max(4, cellHeight×0.85)}px "JetBrains Mono", monospace`, centered glyphs; blanks skipped; fill = `withAlpha(accent, 0.3 + level×0.7)`, `shadowBlur 4` when `level > 0.55`; a terminal cursor block (`accentStrong` α 0.5) on the last revealed cell while `revealed < total`.

### 6.12 `modes/mode-3d.ts` — `class Mode3D` (`id: '3d'`)

**History / why it is built this way.** The first version laid the photo flat on the *floor* (XZ plane), coloured it per-vertex on a ≤96×96 mesh (blocky), and spun the camera 360° forever — so you saw it edge-on, upside-down, or from behind and had to pause the orbit to capture anything. Now the photo hangs like a picture, keeps full resolution as a texture, and the camera holds still unless the user moves it.

Constants: `GRID_MAX_DIM 200`, `GRID_MIN_DIM 8`, `HEIGHT_SMOOTH_RADIUS_FRACTION 0.05` (of the longer grid side, per blur pass — deliberately large: soft volume, no cliffs), `DOME_MIX 0.35`, `EDGE_FLATTEN_FRACTION 0.1`, `RELIEF_BASE_DEPTH 0.26` (of the plane's short edge at ×1), `TEXTURE_MAX_DIM 1400`, `CAMERA_FOV 36`, `FIT_MARGIN 1.1`, `DEFAULT_YAW 0.32`, `DEFAULT_PITCH 0.14`, `YAW_LIMIT 0.6` (~34°), `PITCH_MIN −0.3`, `PITCH_MAX 0.5`, `ZOOM_MIN 0.6`, `ZOOM_MAX 3`, `SWAY_AMPLITUDE 0.34` rad.
```ts
export interface Mode3DOptions { reliefMultiplier: number; autoSway: boolean }
export const DEFAULT_MODE3D_OPTIONS = { reliefMultiplier: 1, autoSway: false };
export const MODE3D_RELIEF_MULTIPLIER_RANGE = { min: 0.25, max: 3 } as const;
configure(partial)            // clamps reliefMultiplier; autoSway boolean
orbitBy(deltaYaw, deltaPitch) // radians; yaw/pitch clamped to the limits above
zoomBy(factor)                // multiplies zoom, clamped to ZOOM_MIN..ZOOM_MAX
resetView()                   // yaw/pitch/zoom back to defaults
```
`process(image)`: grid `cols×rows` (≤200, aspect-preserving, never upsampled); per cell average RGB (`#rrggbb`, kept for the 2D fallback) and Rec.709 luminance; luminance → two `boxBlurChannel` passes (radius `max(1, round(max(cols,rows)·0.05))`) → `shapeHeights`: percentile-normalise 2nd..98th → 0..1, then `h = lum·(1−0.35) + dome·0.35` with `dome = clamp01(1 − (u²+v²)·3.2)` (u,v centred coords). The source `ImageData` is kept privately for the texture. Returns a **fresh payload object every call** (this is what invalidates the mesh).

`render(ctx, progress)`: no payload → clear. Else try WebGL; any failure → dispose + 2D fallback for the instance's life (`reset()` re-enables a WebGL attempt). Hidden offscreen canvas + `THREE.WebGLRenderer` (`antialias`, `alpha:false`, `powerPreference:'low-power'`, pixelRatio 1, sRGB output), blitted with `drawImage` (so `RenderContext` stays 2D-only and PNG export captures exactly what is on screen).
- **Scene:** background `theme.surface`; `AmbientLight(0xffffff, 1.35)`; key `DirectionalLight(0xffffff, 2.3)` at (−3.2, 2.4, 2.6); fill `DirectionalLight(0xffffff, 0.35)` at (3, −1, 2); `PerspectiveCamera(36, aspect, 0.1, 50)`. Ambient-heavy on purpose so the photo keeps its own exposure; the key light rakes across slopes so the relief reads.
- **Mesh** (rebuilt when `meshBuiltFor !== payload`): picture in the **XY plane facing +Z** (plane 2 units on the longer axis, aspect preserved); vertex `(x,y,z) = ((u−.5)·planeW, (.5−v)·planeH, h·depth·edgeFade(u,v))` with `depth = 0.26·reliefMultiplier·min(planeW,planeH)`; `edgeFade` = smoothstep of `min(u,1−u,v,1−v)/0.1`, so the border is always flat and the outline a clean rectangle; UVs `(u, 1−v)`; triangles `(a,c,b),(b,c,d)` (CCW from +Z); `computeVertexNormals()`. **Material:** `MeshStandardMaterial({ map: texture, roughness 0.92, metalness 0 })` (grey fallback colour if there is no source image). **Texture:** the full photo drawn to a canvas (long edge capped at 1400 via high-quality `drawImage`), `THREE.CanvasTexture`, sRGB, `LinearMipmapLinearFilter`/`LinearFilter`, anisotropy 4.
- **Camera:** distance = `max(planeH/2, planeW/2/aspect)·1.1 / tan(fov/2) / zoom` (whole picture just fits, on either axis); `yaw = clamp(this.yaw + sway)`, `sway = autoSway ? sin(progress·2π)·0.34 : 0`; position on a sphere: `(sin yaw·cos pitch, sin pitch, cos yaw·cos pitch)·distance`; `lookAt(0,0,0)`. **`progress` matters only when `autoSway` is on.**
- **Why the limits are what they are:** depth from luminance is only a stylised guess, and any displaced flat photo smears at steep angles (parallax). At ±34° / these depths no reachable view looks broken; a first attempt at ±49° and depth 0.4 visibly stretched faces.
- **2D fallback** (also what jsdom tests exercise): per cell a raking-light shade from neighbouring heights (`shade = clamp01(0.55 + (dx·−0.6 + dz·−0.75)·1.6 + h·0.15)`), **letterboxed** to the image aspect (uniform square cells, grid centred), and **always fully drawn** (ignores `progress` — the timeline no longer runs by default in 3D, so a progress-driven reveal would leave it blank).
- `reset()`: disposes WebGL (geometry/material/**texture**/renderer), clears payload + source image, resets the view. `useEngine` also calls `resetView()` on every new upload.

## 8. Design decisions & assumptions (moved from the old README)

- **2D = posterization** (6 levels/channel), not true vectorization — keeps the pipeline-validation mode simple.
- **Blur = box blur on a summed-area table** (radius-independent cost); Gaussian would be a drop-in upgrade.
- **1600 px max upload edge** bounds cleanup cost/memory (worker keeps the page responsive; the cap still bounds work).
- **`main.tsx`, not `main.ts`** — it mounts JSX. Everything under `src/engine/` is plain `.ts`.
- **`RenderPayload` is a discriminated union** (`kind`): raster / histogram / ascii / relief3d. No placeholder variant remains.
- **Sketch `Layer` = one pen stroke**, not a semantic layer; `ImageMeta.layers` = stroke count.
- **Sketch point extraction is grid-bucketed** with a fixed budget → predictable cost regardless of texture.
- **Sketch ordering is a spatial hash grid** (exact, not approximate) — benchmarked ≈ 106 ms at 20 000 points, so the 8000-point slider ceiling is safe.
- **Histogram uses a sqrt height scale** (linear lets one peak flatten everything; log over-compresses).
- **Histogram R/G/B lines are literal red/green/blue** even though everything else is themed.
- **ASCII cols track image width**, rows use a fixed 0.5 glyph-aspect correction; ramp maps brighter → denser.
- **Mode3D never widens `RenderContext`** (a canvas binds one context type for life); it renders offscreen and blits.
- **Mode3D mesh ≤ 96×96 ≈ 9.2 k vertices / 18 k triangles**; lighting is fixed (raking key + dim fill + ambient) so relief reads on any photo.
- **`three` is a large dependency** (bundle ≈ 695 kB / 188 kB gzip). Lazy-loading Mode3D via dynamic `import()` is possible but needs an async-capable registration path in `useEngine` — documented, not done.
- **"Share" = OS share sheet only**, not a shareable URL (that needs server storage, out of scope).
- **AI path-feeder returns tuning guidance** (focus box + detail level) for the classical Sketch pipeline, not raw coordinates — more reliable and keeps the deterministic pipeline in charge.
- **One rule for settings:** every option change re-runs `process()` via `Controller.switchTo(sameId)` and replays the animation. Simple beats micro-optimising which options are render-only.

## 9. Backend & dev server reference

### 9.1 `api/_shared/errors.ts`
`class ValidationError extends Error` (name `'ValidationError'`) → HTTP 400. `class ModelOutputError extends Error` (name `'ModelOutputError'`) → HTTP 502.

### 9.2 `api/_shared/anthropic-client.ts`
- `const ANTHROPIC_API_URL = 'https://api.anthropic.com/v1/messages'`, `ANTHROPIC_VERSION = '2023-06-01'`, `MODEL = 'claude-haiku-4-5-20251001'` (the single swap-point for provider/model).
- `class AnthropicApiError extends Error { readonly status: number | undefined }`.
- `interface AnthropicImageMessage { imageBase64: string; mediaType: 'image/jpeg' | 'image/png'; prompt: string; maxTokens: number }`.
- `askClaudeAboutImage(message): Promise<string>`: reads `process.env['ANTHROPIC_API_KEY']` (missing → `AnthropicApiError` *before* any fetch); `POST` with headers `content-type`, `x-api-key`, `anthropic-version`; body `{ model, max_tokens, messages: [{ role: 'user', content: [ {type:'image', source:{type:'base64', media_type, data}}, {type:'text', text: prompt} ] }] }`. Network failure → `AnthropicApiError('Could not reach the Anthropic API: …')`; non-2xx → `AnthropicApiError('Anthropic API returned <status>: <first 300 chars of body>', status)`; non-JSON body → error; no `text` content block → error; else returns that block's text.

### 9.3 `api/_shared/handlers.ts`
- `MAX_IMAGE_BASE64_CHARS = 3_000_000` (≈ 2.2 MB decoded; under Vercel's 4.5 MB body limit).
- `validateImageBase64`: must be a non-empty string (`'imageBase64 is required and must be a non-empty string.'`) and ≤ limit (`'Image payload too large — downscale before sending (see backend-spec.md section 6).'`) → `ValidationError`.
- `handleDescribe(body)`: calls Claude with `mediaType 'image/jpeg'`, `maxTokens 300`, prompt "Describe this photo in 2-3 plain sentences, as alt text for someone who cannot see it. Focus on the actual subject and setting, not any artistic rendering style. No preamble, just the description." → `{ description: trimmed }`.
- `handlePathFeeder(body)`: prompt asks for **only** JSON `{"focusRegion": {x,y,width,height}|null, "suggestedDetail": "low"|"medium"|"high", "reasoning": string}` (fractions 0..1 from top-left; null if no single subject). `parsePathFeederResponse`: strips an optional ```` ```json ```` fence; `JSON.parse` failure → `ModelOutputError('Model response was not valid JSON.')`; non-object or array → `ModelOutputError('Model response JSON was not an object.')`. **Lenient normalization**: unknown `suggestedDetail` → `'medium'`; `focusRegion` malformed / any field outside 0..1 / non-finite → `null`; missing `reasoning` → `''`.

### 9.4 `api/_shared/http-error.ts`
`toHttpErrorPayload(err): { status, body: ApiErrorResponse }`: `ValidationError` → 400 with its own message; `ModelOutputError` → 502 `'The AI model returned something this endpoint could not use. Try again.'`; `AnthropicApiError` → its status if `< 500` else 502, message `'The AI service is unavailable right now. Try again shortly.'` (upstream detail never reaches the client); anything else → 500 `'Unexpected server error.'`.

### 9.5 `api/_shared/vercel-types.ts`
Minimal `VercelRequest { method?: string; body?: unknown }` and `VercelResponse { status(code): VercelResponse; json(body): VercelResponse }` (avoids a `@vercel/node` dependency).

### 9.6 `api/describe.ts`, `api/path-feeder.ts`
Default-exported `async function handler(req, res)`: non-POST → `405 { error: 'Method not allowed — POST only.' }`; else run the matching handler with `req.body`, `200 json(result)`; on throw → `console.error('[api/describe]' | '[api/path-feeder]', err)` then `toHttpErrorPayload`.

### 9.7 `dev-server/ai-proxy-plugin.ts`
`aiDevProxyPlugin(): Plugin` — name `'vector-stroke-engine:ai-dev-proxy'`, `apply: 'serve'` (never in the production bundle), `configureServer` mounts `/api/describe` and `/api/path-feeder` middlewares that call the **same** `handleDescribe`/`handlePathFeeder`. Shared `handleRoute`: non-POST → 405 JSON; `readJsonBody` (empty body → `undefined`; invalid JSON → `ValidationError('Request body was not valid JSON.')`); success → 200; errors → `console.error('[ai-dev-proxy]', err)` + `toHttpErrorPayload`. Only the transport differs from production, so dev cannot drift from deployment.

Verified locally (dev server): GET → 405; POST `{}` → 400; POST with image and no key → 502 generic message.
**Not verifiable here:** an actual Vercel deployment (the `api/` files use extensionless relative imports as originally written). Test with `vercel dev` or a real deploy before relying on it.

## 11. Known gaps & ideas (not done — intentionally)

1. **No UI calls `/api/describe` or `/api/path-feeder`.** A "Describe" card and a "Smart guide" button (using `focusRegion` to bias Sketch sampling and `suggestedDetail` to move the edge percentile) is the natural next step.
2. **`validateImageBase64` does not strip a `data:image/…;base64,` prefix** and always sends `image/jpeg`; the contract says the client must send raw base64 JPEG (per `docs/backend-spec.md` §6). Accepting data URLs + PNG/WebP would be a small hardening.
3. **No rate limiting** on the paid endpoints (needs shared state such as Vercel KV/Upstash).
4. **Sketch SVG export hard-codes `stroke-width="1.4"`** (StrokeData carries no width), so it ignores the Stroke-thickness slider.
5. **Free / offline alternatives to Claude** (from the deleted review, kept as ideas): compute path-feeder classically in the browser — `suggestedDetail` from mean Sobel magnitude thresholds, `focusRegion` from the densest edge window — needs no API at all; for describe, run an in-browser captioner via Transformers.js (`Xenova/vit-gpt2-image-captioning`), or swap `anthropic-client.ts` for a free-tier provider (Gemini Flash, Groq, Cloudflare Workers AI, OpenRouter free models). The provider is isolated to one file by design.
6. **Lazy-load Mode3D/three** to shrink the initial bundle.
7. Vercel deployment of `api/` unverified in this environment (see 9.7).

**Behaviour worth knowing**
- Sketch: **Detail** ↑ = more/finer lines; **Line cleanup** ↑ = drops more small specks; **Shading** 0 = pure line art. Genuinely noisy, low-contrast, structureless images give few or no lines (by design — the old algorithm drew a maze there).
- 3D depth is a *stylised guess from brightness*, not real depth (a single photo has none). It is deliberately smooth and shallow, and the camera range is limited, because displaced flat photos smear at steep angles.
